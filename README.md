# РейсКонтроль — веб-MVP для защиты проекта УрФУ (заявка № 7684, Startup Guide)

Локальный русскоязычный веб-прототип сервиса согласования условий, приёмки и передачи рейсов в бухгалтерию для производственных и оптовых компаний Свердловской области.

## Как запустить демо

Требуется только Node.js 20+ (внешние зависимости и API-ключи не требуются).

```bash
cd urfu-freight-mvp
npm start
```

Приложение откроется по адресу: **http://127.0.0.1:4173**

Запуск автоматических тестов:

```bash
npm test
```

## Что моделируется локально в MVP

В целевой архитектуре проектного документа предусмотрены веб-кабинет, API, PostgreSQL, закрытое хранилище документов, а на следующем этапе — независимый реестр (блокчейн), платёжный партнёр и интеграция с 1С.

В данном демонстрационном MVP:
- **Хранение состояния** — локальный JSON-файл `data/state.json` (атомарная запись; состояние сохраняется после перезагрузки страницы и перезапуска сервера).
- **Роли и доступ** — переключатель 4 вымышленных деморолей в шапке (`Логист`, `Перевозчик`, `Получатель`, `Бухгалтер`) без внешней авторизации. Перевозчик видит только назначенные ему рейсы.
- **Контроль целостности (SHA-256)** — локальное вычисление контрольной суммы SHA-256 согласованной версии условий. Показывает изменение содержимого файла («Совпадает» / «Файл отличается»). Отправка транзакций в блокчейн и банковский перевод не имитируются.
- **Выгрузка для 1С** — формируется и скачивается демонстрационный CSV-файл с пометкой *«Демонстрационная выгрузка для сверки с 1С»* и идемпотентным номером распоряжения (повторный клик не создаёт дубль). Интеграция с живой 1С не выполняется.
- **Биллинг** — не реализован (подписка грузоотправителя 3 000 ₽/мес при бесплатном доступе перевозчика остаётся бизнес-гипотезой).
- **Данные** — все организации, имена, контакты и документы вымышлены. Кнопка **«Сбросить демо-рейс»** возвращает только демонстрационный рейс `Р-2026-041` в исходное состояние (10:00), сохраняя рейсы, созданные вручную.
